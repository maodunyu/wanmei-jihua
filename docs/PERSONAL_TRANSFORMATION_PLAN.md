# 完美计划：90 天个性化蜕变计划（产品需求基线）

## 产品定位

完美计划不是通用课程列表或单纯训练打卡器。核心流程是：了解用户当前身体、健康限制、生活习惯和训练条件，再结合用户目标生成可执行的 90 天计划，并根据真实执行结果持续调整。

## 首次使用主流程

1. 欢迎页说明评估用途、数据保存方式和非医疗边界。
2. 分步骤完成个人评估；支持保存草稿、返回修改和跳过非必填项。
3. 生成身体现状摘要和目标可行性说明。
4. 生成 90 天计划预览，用户确认后才写入正式训练日程。
5. 进入每日执行页；每周复盘并更新后续计划。

## 评估问卷字段

### A. 基础资料
- 年龄（必填；用于估算而非诊断）
- 生理性别/公式所需参数（可选择不提供；说明其用途）
- 身高、当前体重（目标计算所需）
- 腰围、臀围、体脂率（可选；注明测量方法和数据来源）
- 体重单位、身高单位

### B. 目标
- 主要目标：减脂、增肌、塑形/体态、维持体重、提升体能
- 目标体重或围度（可选）
- 期望周期；默认展示 90 天，但不得承诺必达结果
- 用户最在意的部位/能力和成功标准

### C. 健康与限制
- 伤病、疼痛、活动受限、医生给出的运动限制
- 慢性病/妊娠等需要专业指导的情况（允许选择不回答）
- 运动中胸痛、晕厥、异常呼吸困难等风险提示；出现危险信号时停止自动处方并建议寻求医疗帮助
- 不做疾病诊断，不替代医生或注册营养师建议

### D. 训练基础与资源
- 训练经验：新手、恢复训练、规律训练
- 每周可训练天数、偏好日期、每次可用时间
- 训练地点：家中/健身房/户外
- 可用器械；喜欢和不喜欢的运动
- 日常活动水平、步数（可选）

### E. 饮食与作息
- 饮食模式、忌口/过敏、饮食偏好
- 工作/生活作息、睡眠时长与质量
- 外食频率、做饭条件、饮水习惯
- 不要求用户一开始精确记录每一餐

## 90 天计划输出

- 当前状态摘要：已知数据、缺失数据、估算值和不确定性分开显示
- 目标分阶段：第 1–2 周适应与建立基线；第 3–6 周稳定执行；第 7–12 周渐进与复盘（阶段长度可按个体情况调整）
- 训练：每周安排、动作、组数、次数/时长、强度提示、休息日和替代动作
- 饮食：每日能量建议区间、蛋白质等营养目标、食物组合示例和可替换选择
- 恢复：睡眠、休息、活动量与恢复提示
- 每个建议显示简短理由、依据的数据和可调整项
- 用户确认后再应用训练计划；不覆盖已有训练历史或用户自建计划

## 动态调整闭环

- 每日轻量记录：训练完成情况、饮食执行感受、疲劳/疼痛、体重（可选）
- 每周复盘：优先使用 7 日体重趋势/周均值、腰围变化、训练表现、执行率和主观恢复，不根据单日体重波动调整
- 判断顺序：数据是否足够 → 执行情况 → 水分/测量误差等干扰 → 训练恢复 → 再考虑调整能量或训练量
- 每次调整给出原因、调整幅度、预期观察窗口；保留用户确认/撤销
- 体重变化过快、疼痛增加、疲劳持续或风险信号出现时，降低强度并提示专业评估

## 技术原则

1. **免费基础规划优先**：基础评估、规则计算、计划草案和追踪不依赖外部 AI API。
2. **AI 是可选增强**：用于解释、问答和辅助复盘；未经用户同意，不把个人健康/身体数据发送给第三方模型。
3. **复用 OpenGym**：复用动作库、训练日程、训练日志、渐进训练、体重/围度记录；不重复造训练记录引擎。
4. **数据透明**：区分用户输入、设备读取、算法估算和 AI 建议；用户可查看、修改、导出和删除。
5. **移动端优先、离线可用**：评估草稿和基础计划可在手机本地完成；无网络时仍能查看计划和记录训练。
6. **不夸大承诺**：90 天是规划周期，不是保证减重/塑形结果的承诺。

## 当前代码基线与差距

已在仓库中发现：
- `CoachIntake.jsx`：现有问卷包含目标、训练经验、每周训练天数、单次时长、器械、限制/偏好/备注。
- `CoachChat.jsx` 与 `coach-api.js`：已有 AI Coach 对话、计划请求、建议确认流程。
- `coach-local.js` / `CoachSetup.jsx`：支持手机本地 BYOK 模式，但需要用户自备 API key；这不等于免费离线规划。
- `bodyweight.js`、`Measurements.jsx`、`Home.jsx`：已有体重趋势和身体围度记录基础。
- `useStore.js`：已有本地状态持久化和移动端数据存储。

当前缺口：
- 首次启动还没有以完整身体/生活评估为中心的产品流程。
- 现有问卷缺少基础身体数据、饮食、睡眠、日常活动、目标期限与风险分层。
- 还没有经测试的、无需 API 的个性化 90 天基础计划生成与动态调整闭环。
- 饮食营养数据与每日饮食计划需要单独设计，不能把训练计划误称为完整减脂方案。

## 实施顺序

### Phase 1：本地评估与计划核心
- 新建独立的评估数据模型和版本迁移。
- 实现分步问卷、草稿保存、修改入口和隐私说明。
- 实现可解释的规则计算：BMI 仅作粗略参考；能量估算标记为估算并设置保守边界；高风险情况不自动生成强度/热量处方。
- 生成 90 天计划预览，确认后再写入训练日程。
- 加测试覆盖输入边界、缺失数据、单位换算、风险拦截和计划不覆盖历史。

### Phase 2：训练与饮食执行
- 把计划映射到 OpenGym 现有 routines / week / dayPlan 结构。
- 新增饮食目标和简单食物/餐次记录；先做透明的营养估算，不做未经验证的拍照热量承诺。
- 增加每日执行页和每周复盘页。

### Phase 3：动态调整与 AI 增强
- 基于趋势、执行率、训练表现和恢复反馈给出可撤销调整。
- AI 仅作为可选解释/对话层，保留本地规则引擎作为可靠底座。
- 评估后续接入 Health Connect 等健康数据源的价值和权限范围。

## 验收标准（Phase 1）

- 用户可以不配置任何 API key 完成评估并得到基础 90 天计划草案。
- 评估可以中途退出、恢复、修改；用户未确认前不改变现有训练安排。
- 输出能说明哪些数据是用户输入、哪些是估算。
- 缺少关键数据时要求补充或显示区间，不伪造精确结果。
- 有伤病/健康限制时不输出不适当训练建议，并给出清晰提示。
- 新功能通过自动化测试，Android GitHub Actions 构建成功。
